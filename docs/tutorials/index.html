Build the thymol DOS pipeline, test first

Three notebooks turn a thymol crystal into a vibrational density of states you can set beside the TOSCA spectrum. You write the tests, watch them fail, then write the code.

Set up the environment

The environment in md/ is installed. When I checked: Python 3.14, OpenMM 8.6.1, openmmforcefields 0.16.0, openff-toolkit 0.19.0, RDKit 2026.3.1, MDANSE 2.0.1, marimo 0.25.2, pytest 9.2.0. If md/.pixi is missing on your machine, run the install below.

Install the environment, if it is missing

cd md
pixi install

It ends with a line saying the environment was installed. Do not use pixi add or pixi update without deciding it first: they re-solve the whole stack.

Check the tools import

pixi run python -c "import openmm, openmmforcefields, rdkit, marimo; print(openmm.__version__)"

It prints a version number and no traceback.

Run the test runner once

pixi run pytest

Right now it reports that no tests ran. That is the correct starting point.

How a marimo file works

A marimo notebook is an ordinary Python file. Open one for editing, run it headless, or test it:

pixi run marimo edit 01_system.py   # interactive editor in the browser
pixi run python 01_system.py         # runs the notebook as a script
pixi run pytest 01_system.py         # runs cells named test_...

Functions marked @app.function can be imported by other files, if they are pure: they may use only other pure functions and the imports and constants in an app.setup block. That is why the logic lives in modules next to the notebooks, in files like md/dos.py, and the notebooks only call them and show results.

The loop for every function

  1. Write one small test for one behaviour. Run pixi run pytest.
  2. Read the failure. It must fail because the feature is missing, not because of a typo.
  3. Write the least code that makes it pass. Run the tests again.
  4. Tidy up with the tests green.
  5. Add an entry to LOG.md. Take the time from date '+%F %H:%M' instead of typing it.

The DOS tests in page 3 were run against the reference code shown there: three failed with a stub, three passed with the implementation. The OpenMM tests in pages 1 and 2 were written before the environment was checked and have not been run: run them as you go and trust the failures you see over my hints.
